### 共用约束

1. 当前 Agent 顺序完成，不创建子代理，不使用并行任务标记；不自动创建分支、提交、部署或发布。
2. 前端 Vue 3/TypeScript/Element Plus；后端 Java 21/Boot/Security/Spring JDBC；MySQL 8.4 与 Redis；具体补丁按设计基线核对、锁定。Token 为随机 Bearer 凭据，摘要键仅保存在 Redis，数据库用户 auth_version 负责全部旧 Token 撤销。
3. 按周边代码风格排序；Controller 不主动抽取公共方法。非 Controller 只有本次产生的重复超过50行且至少3处使用等用户全部条件满足时，才允许主动抽取。
4. 新增/修改方法有方法注释；重要业务分支有简洁注释；实体和 DTO 每个字段使用 Javadoc 注释。
5. 每个 Controller 入口以及关键业务节点、必要阶段都有 [模块] 功能点 关键参数 日志；不记录密码、Token/摘要、Authorization 或完整联系资料。运行日志与持久化操作/登录记录分别实现。
6. ID/version 用十进制字符串传输；状态和业务枚举用固定整型编码，不使用字符串枚举或 Java ordinal；时间以 UTC 存储/API ISO 8601 输出。
7. 用户账号不可改且区分大小写，新增默认启用；手机号邮箱选填不唯一。密码和 auth_version 同事务更新，旧 Token 不因重新启用恢复。授权变更下一次请求生效，不使正常 Token 强制退出。
8. 日志写入独立事务且失败不阻断原业务；禁止把数据库回滚描述为可以回滚 Redis。Redis 不可用默认拒绝认证，不降级放行。
9. 必要验证随任务完成；使用后端测试、真实 MySQL/Redis 关键集成验证及前端组件测试/类型检查/构建。不运行端到端测试，不为简单可逆变更机械新增测试。
10. 配置与来源未核实的能力不得写成既有实现；无存量数据迁移负担，仅交付新建迁移。实现阶段生成实际记录和状态，本阶段不运行代码或迁移。

### T001 建立前后端工程与数据基础

- 目标：提供后续所有业务任务需要的可构建工程、数据库结构、Redis 连接及统一接口约定。
- 覆盖场景：公共前置，服务 S-001～S-010；不单独交付完整场景。
- 前置依赖：无。
- 包含范围：Java/Vue 工程、7 张表及约束索引、连接和认证期限配置、响应/错误/枚举/时间转换、测试基础。
- 排除范围：初始化账号与权限由 T002 承接；业务 API、页面及日志采集分别由后续任务负责。
- 实现位置：拟新增 backend/、frontend/、backend/src/main/resources/db/migration/。包根为 backend/src/main/java/com/muqiu/managentcenter/，简称目录均位于该包根下。
- 设计依据：详细设计 §1.1、§6；接口设计 §1.1、§3.1～3.3；数据结构设计 §2.0～2.7、§3。

实现步骤：

1. 建立拟新增 backend/ Maven 工程及 frontend/ Vue 3 + TypeScript 工程，按设计基线锁定依赖补丁、前端锁文件；核对 Java 21、Boot BOM 与 Redis/Flyway 兼容，不静默改换架构。
2. 配置 MySQL、Redis、auth.token-ttl 与环境凭据校验；期限必须为正数，秘密从环境读取。提供开发配置示例，不放真实密码或 Token。
3. 用 Flyway 定义 sys_user、sys_role、sys_permission、sys_user_role、sys_role_permission、sys_operation_log、sys_login_log 的字段、索引、CHECK 和外键；username/name 使用设计的大小写敏感排序规则，不建立登录会话表。
4. 建立 ApiResponse、统一异常处理、固定整型枚举和 ID/版本字符串转换、UTC 时间转换；未知请求字段拒绝。落实 BCrypt UTF-8 字节上限及联系方式规范，不预设额外密码业务策略。
5. 准备后端可复用 MySQL/Redis 集成验证环境及前端组件测试、类型检查、构建配置，不新增端到端测试流程。

完成标准：

- 前后端工程可构建；配置非法明确失败，不输出敏感值。
- 新数据库可应用迁移；重复启动不重复建表，唯一键、外键和 CHECK 真实有效，7 张表与设计一致。
- Admin/admin 账号能够分别存储，同账号重复被唯一键拒绝；重复手机号/邮箱不因唯一约束失败。
- 统一包装、状态整型、ID/版本字符串和 UTC 时间序列化符合接口契约；所有字段注释及日志约束已落实。

- 包含范围：幂等权限定义、初始化管理员、命名锁及启动保护，包含两类日志查看权限。
- 排除范围：不提供运行时权限 CRUD 或管理员自助创建接口；前端菜单生成由 T003 承接。
- 实现位置：拟新增 backend/src/main/java/com/muqiu/managentcenter/system/、permission/、resources/db/migration/。包根为 backend/src/main/java/com/muqiu/managentcenter/，简称目录均位于该包根下。

实现步骤：

### T003 交付 Token 登录退出与后台权限入口

- 目标：用户可登录进入后台，后端使用 Redis Token 独立认证授权，前端按有效权限展示导航。
- 覆盖场景：S-002,S-008。
- 前置依赖：T001、T002。
- 包含范围：I-002、I-003、I-004，RedisTokenStore、TokenAuthenticationFilter、AuthorizationManager、前端登录/退出/空首页与路由/按钮权限基础。
- 排除范围：改密由 T004；管理 API/页面由 T005～T007；持久化登录日志与请求审计上下文由 T008。
- 当前实施结果：AuthService/AuthController、TokenAuthenticationFilter、AuthorizationManager、安全配置及前端登录/身份/导航已补齐；认证与前端组件验证通过，动态授权已在 T007 组合验证。最终全部场景仍由 T009 收敛。
- 实现位置：拟新增 backend/src/main/java/com/muqiu/managentcenter/system/、security/；frontend/src/api/、stores/、router/、layouts/、views/LoginView.vue。包根为 backend/src/main/java/com/muqiu/managentcenter/，简称目录均位于该包根下。
- 设计依据：详细设计 §2、§3.2～3.4、§4.2、§4.8、§5.1～5.3；数据结构设计 §3、§4.1；接口 §2.2～2.4。

实现步骤：

1. 实现精确账号与 BCrypt 验证、dummy 校验和统一 40102；用户行锁内复核密码、状态和 auth_version，再 SET NX PX 签发随机 Token，事务完成后返回 token/tokenType/expiresAt/user。
2. 只在 Redis 保存 Token 摘要键及用户/认证版本/时间，不保存权限、密码或原始凭据；Token TTL 与 expiresAt 同时校验。退出 DEL 当前键，失败不宣称退出成功。
3. 处理 SET 成功后事务失败的补偿 DEL，SET 超时按失败处理；孤立未返回 Token 等待 TTL 回收，不自动重试登录。
4. 认证只接受 Bearer Header，比对用户启用及认证版本；缺失/失效 40101，Redis 不可用 50301，权限读取失败默认拒绝。业务权限逐请求 DISTINCT 查询，未映射入口 denyAll；超级管理员不豁免认证。
5. 实现 me、菜单父容器补全而不隐式授权、query 页面守卫和操作按钮权限；Token 放 sessionStorage，页面重载/路由进入/焦点/业务请求后的刷新遵循设计。
6. 登录/退出前端状态与错误一致，不使用认证 Cookie/CSRF/JWT/刷新 Token；生产 HTTPS，同源开发代理，401 清身份，503 停止请求，不自动重放写操作。

完成标准：

- 通过接口与前端组件验证正确/错误/停用/未知账号登录、无角色账号、退出及旧 Token 重放，状态/数据符合契约。
- 多个 Token 可同时登录，退出只撤销当前 Token；Redis 故障不放行，TTL 到期不可使用。
- 手动地址与直接请求均不能越权，只有查询权不会自动获得写权限；菜单、页面、按钮使用同一语义。
- T007 完成后组合验证授予/撤销权限的下一次请求生效；本任务不提前宣称动态授权完整验收通过。

### T004 交付本人改密与全部 Token 失效

- 目标：登录用户能验证原密码并修改本人密码，成功后全部已有 Token 失效。
- 覆盖场景：S-003,S-008。
- 前置依赖：T003。
- 包含范围：I-005、改密页面/弹窗、密码与认证版本的原子更新。
- 排除范围：管理员重置由 T005；密码操作的持久化记录由 T008。
- 实现位置：拟新增 backend/src/main/java/com/muqiu/managentcenter/system/、user/UserRepository；frontend/src/views/、layouts/。包根为 backend/src/main/java/com/muqiu/managentcenter/，简称目录均位于该包根下。
- 设计依据：详细设计 §4.3、§5.1～5.3；接口 §2.5；数据结构设计 §2.1、§3.1。

实现步骤：

1. 固定操作对象为当前认证用户，Body 不接收用户 ID；用户行锁内验证启用状态与原密码。
2. 同一事务更新密码摘要、version/updated_at 与 auth_version，不遍历 Redis，不主动签发新 Token。
3. 处理原密码错误、非法/超字节输入、未知字段与数据库失败；回滚时密码和认证版本一起保持。
4. 成功后前端清 Token/身份回登录页；失败不退出；入口/结果日志不包含任何密码。

完成标准：

- 使用两个独立 Token 改密，成功后两者均 40101，新密码可登录、旧密码不可登录。
- 原密码错误、指定他人字段、数据库失败均不改变密码及认证版本；失败改密不误撤销原 Token。
- 拟验证与并发登录的用户行锁顺序：旧密码不能在改密提交后新签发有效登录。

### T005 交付用户管理启停及密码重置

- 目标：管理员按独立操作权限管理用户资料、状态及密码，不允许修改账号或删除用户。
- 覆盖场景：S-004,S-005,S-008。

- 设计依据：详细设计 §3.5、§4.9～4.10、§5.5；接口 §2.23～2.26、§3.3；数据结构设计 §2.6～2.7；需求 S-009/S-010。

实现步骤：

2. 将真实认证用户快照在 SecurityContext 清理前复制到 RequestAuditContext；未认证操作人为空。BodyAdvice 只提取 DTO 白名单，非法 JSON/账号可为空，不缓存原始 Body，不序列化密码/Token。

4. 链路结束后由独立 Bean REQUIRES_NEW 保存一次，request_id 唯一键防重复；保存异常捕获为 AUDIT_WRITE_FAILED ERROR，附安全 requestId 和类型，告警规则承接，不能改变原 HTTP/业务结果或回滚密码状态。

完成标准：

- 验证成功、回滚、参数错误、401/403、409及 Redis 故障结果准确；已提交但响应失败不被谎记回滚。

- 角色删除/用户资料变化后历史仍可查看，所有输出/入库字段不含敏感凭据或完整联系方式。
