### 1.1 通用调用约定

- 除 login 外均要求有效 Bearer Token；初始化无 HTTP 入口。删除原 I-001 获取 CSRF 令牌接口，其余 I-002～I-026 编号与路径保持，不复用删除编号。
- 客户端发送 Authorization: Bearer <token>；Token 必须来自登录响应。不接受 Cookie、Query 或 Body 作为受保护请求的登录凭证。生产 HTTPS，不在 URL、日志、错误响应中传递 Token。
- 登录成功返回 token、tokenType、expiresAt 和用户资料；前端保存到当前标签页 sessionStorage 和内存，重载后通过 me 重建。每次登录生成独立 Token，其他 Token 保持有效，除非退出、过期或用户认证版本发生变化。
- 所有业务接口先验证 Token，再检查账号启用、认证版本和最新权限，然后查询目标。超级管理员只豁免业务权限判断，不豁免认证、输入校验或保护规则。未声明业务接口 denyAll。
- 不使用认证 Cookie，不提供 CSRF 接口/Token；客户端明确附加 Bearer Header。默认同源代理，未配置的跨域请求拒绝。
- 未知 Body 字段 40001，ID、version 为十进制字符串；时间为 UTC ISO 8601。状态整数 0=停用、1=启用。用户 authVersion 不对外输出。
- 联系资料空字符串/纯空白归一 NULL；非空裁剪首尾空白后校验。账号、密码不裁剪、不转小写，不默默截断。
- 列表固定 id DESC；page 默认 1、size 默认 20 且 1～100，同一只读事务快照读取列表和总数。
- PUT 完整替换资料或集合；修订号防并发覆盖，不提供通用幂等键，不自动重放写请求。
- Redis 不可用时 login 及所有受保护请求返回 50301；数据库或其他内部异常按 50000。版本不符、Token 缺失/撤销/过期返回 40101。
- 手机号、邮箱仅输出给本人和有 user:query 权限者；日志禁止记录密码、Token、Authorization、Token 摘要和完整联系资料。
- 日志查询权限互相独立，可查询全平台对应类型记录；不会因 user:query 或 role:query 自动获得日志查看权限。
- 所有请求生成服务端 UUID，并通过 X-Request-Id 响应 Header 返回；操作记录和登录日志关联该标识。日志写入失败不新增业务错误码、不改变原 HTTP/JSON 结果，运行错误与告警报告记录缺失。
- 日志列表固定 occurredAt DESC、id DESC；账号按大小写敏感完整值精确筛选，时间范围为 [startTime,endTime)，全部筛选条件 AND。两类日志不提供写入、修改、删除、清空或导出的公开接口；记录查询不生成操作记录。

## 2. 接口详情

所有接口通用 Token 认证、校验及响应规则见 §1.1、§3。业务权限允许超级管理员。全部接口可能返回 50000 和 50301；具体错误码见 §3.2。

### 2.2 I-002 登录

**请求：** `POST /api/auth/login`。实现入口：`AuthController.login(LoginRequest)`。

权限：公开。

#### 请求参数

| 参数 | 位置 | 类型 | 必填 | 约束／默认值 | 说明 |
|---|---|---|---|---|---|
| username | Body | String | 是 | 非空，最长 64 字符；区分大小写，禁止首尾空白 | 登录账号 |
| password | Body | String | 是 | 非空，UTF-8 最长 72 字节；不裁剪 | 密码 |

#### 请求示例

```json
{
  "username": "Admin",
  "password": "example-password"
}
```

#### 返回数据

成功 HTTP 200，公共包装见 §3.1。data 类型：**LoginData**，完整字段见 §3.3；null 表示无业务返回值。所有返回不包含 password_hash、密码或 Token 摘要；只有登录响应包含原始 Token，其他响应不回显 Token。

#### 返回示例

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "user": {
      "id": "1",
      "username": "Admin",
      "displayName": "管理员",
      "phone": null,
      "email": null,
      "status": 1,
      "superAdmin": true,
      "version": "0",
      "createdAt": "2026-10-09T08:00:00Z",
      "updatedAt": "2026-10-09T08:00:00Z",
      "roles": []
    },
    "expiresAt": "2026-10-09T10:00:00Z",
    "token": "example-opaque-token",
    "tokenType": "Bearer"
  }
}
```

#### 异常返回与调用约定

可能错误码：40001、40102、40302、50000，定义及 HTTP 状态见 §3.2。

每次成功登录签发独立 Token 并写 Redis TTL，登录响应返回凭据。其他 Token 不因本次登录撤销；客户端替换当前标签页保存值，旧值如需主动撤销应先退出。示例时间仅说明格式，不规定寿命。

## 3. 公共返回结构与数据对象

### 3.1 包装

| 字段 | 类型 | 说明 |
|---|---|---|
| code | Integer | 成功 0；错误见 §3.2 |
| message | String | 成功 success；错误为可展示中文，不含堆栈或敏感值 |
| data | Object/Array/null | 由接口确定，错误时 NULL |

成功统一 HTTP 200，包括创建与删除。拒绝、冲突和失败使用真实 HTTP 状态，不能全部返回 200。

```json
{"code":40301,"message":"无操作权限","data":null}
```

### 3.2 错误码

| 错误码 | HTTP 状态 | 含义 | 行为 |
|---|---|---|---|
| 40001 | 400 | 参数或格式错误 | 不保存，提示字段规则 |
| 40002 | 400 | 本人改密原密码错误 | 密码及已有登录保持不变 |
| 40101 | 401 | Token 缺失、无效、过期、已撤销或用户认证版本不匹配 | 清除客户端 Token 和身份，引导登录 |
| 40102 | 401 | 登录账号或密码错误 | 统一提示，不区分账号不存在和密码错误 |
| 40301 | 403 | 缺少业务权限 | 不执行，前端刷新当前权限 |
| 40302 | 403 | 凭据验证正确但账号停用 | 不签发 Token |
| 40401 | 404 | 授权范围内的目标不存在 | 不保存；删除重复也返回此码 |
| 40901 | 409 | 登录账号或角色名称重复 | 不保存；并发唯一键冲突同样映射 |
| 40902 | 409 | 修订号过期或并发冲突 | 回滚，刷新数据后重试 |
| 40903 | 409 | 角色仍关联用户 | 先解除全部关联，包括停用用户 |
| 40904 | 409 | 超级管理员保护 | 不允许停用 |
| 50000 | 500 | 服务端或数据库异常 | 回滚，不展示内部错误 |
| 50301 | 503 | Redis 认证服务不可用 | 不签发 Token、不放行；退出未完成，不自动重试写请求 |

已登录用户被停用且 Token 已失效，后续请求返回 40101；40302 仅用于新登录的正确凭据。数据库不可用时 50000，Redis 不可用时 50301，均默认拒绝，绝不凭旧身份或旧权限放行。
